# ML code and training audit — 6 October 2026

Review scope: **all 58 non-cache files under `ml/`**, including 44 Python files, 5 YAML configurations, 5 generated package metadata text files, the results JSON, Dockerfile, Makefile, and requirements. All 44 Python files parsed successfully with `ast.parse`. The 44 `.pyc` files in `__pycache__` are generated copies of reviewed Python sources and were counted but not reverse-engineered. No checkpoints, dataset files, exported feature caches, or model export reports currently exist under `ml/`; the reported accuracy could therefore not be reproduced against trained weights. Android files were read selectively to check contracts; their complete review belongs to the Android audits. Existing code and user changes were not modified. No training, package installation, or large download was started.

## Executive assessment

The implementation has useful foundations: tiny offline models, explicit LFCC and NumPy reference front ends, real-data export paths, explicit score polarity, tree transpilation, phone-image corruption augmentation, and model hashes. However, **current metrics cannot establish reliable detection of current Stable Diffusion, Gemini/Nano Banana, ChatGPT image generators, or arbitrary synthetic speech**. The pipeline has label inversions in downloaders, an execution-blocking audio dtype mismatch, reused validation/test data, incomplete mobile preprocessing equivalence, and exports hardcoded for thumbnail training. Correct these before spending substantial compute on larger datasets.

The visual JSON reports AUC 0.9560 and accuracy 88.9% on 4,000 `genimage/val` images. The downloader stores **CIFAKE**, not official GenImage, in that directory. The audio JSON reports AUC 0.9760 and EER 5% on only 280 files; the downloader stores a small **Gary Stafford dataset**, not official ASVspoof2019, in the `asvspoof2019` directory. Directory names and old comments cannot be used as evidence of actual training coverage. The source dataset identity should be an immutable manifest field.

## Findings in priority order

### P1 — Proven: dataset downloaders invert real/fake labels

- `ml/scripts/download_all_datasets.py:84–85` assumes the downloaded CIFAKE label 0 means real. The actual repository metadata assigns **0 = FAKE, 1 = REAL**. Re-running this function labels generated pictures real and authentic pictures fake. The function is presently bypassed by the script's `main` (`:276–277`), so the defect is proven in the function; the origin and polarity of the shipped visual model cannot be established without its training manifest.
- `ml/scripts/download_highres_audio.py:43–44` and `ml/scripts/download_advanced_datasets.py:51–52` assume label 1 means real for `garystafford/deepfake-audio-detection`. The source card and viewer assign **0 = real, 1 = fake**. These functions invert audio labels. They also write into locations that can mix with previously downloaded data of the opposite convention.
- Read `dataset.features['label'].names` and map semantic class names explicitly into the app contract, 0 real/1 synthetic. Refuse unknown or missing mappings. Save source revision, mapping, original item ID and source path, and inspect representative examples before training. Do not silently flip scores after evaluation to hide a training-label inversion.

Primary evidence: [CIFAKE metadata](https://huggingface.co/datasets/dragonintelligence/CIFAKE-image-dataset/blob/main/README.md) and [Gary Stafford audio card](https://huggingface.co/datasets/garystafford/deepfake-audio-detection). These source checks were read on 6 October 2026. The latter source currently has 1,866 files, a single train split, six synthesis platforms, and real speech from 14 original recordings. Source cards are mutable; pin a revision for reproducibility.

### P1 — Reproduced: current audio training cannot consume its own features

- `ml/src/data/lfcc_frontend.py:132` promotes buffers to float64; the DCT and normalization keep this dtype through the return at `:188–189`.
- `ml/src/data/lfcc_extractor.py:86–87`, `asvspoof_dataset.py:114–117`, and `inthewild_audio.py:142–153` return that float64 tensor without conversion.
- `ml/src/training/trainer.py:109` and `:151` move inputs to a device but do not convert dtype. `LCNNMFMAudio` initializes float32 Conv2d weights and bias.
- Cheap CPU reproduction with a random 64,000-sample input produced `torch.float64 (1,1,401,40)` and `RuntimeError: Input type (double) and bias type (float) should be the same`. Casting the same feature tensor to float32 successfully ran the LCNN. CUDA autocast does not make float64 input a float32/float16 model input.
- Keep the double-precision reference/DSP computation if parity requires it; explicitly return or batch-convert **float32** for the neural network. Add one actual dataset-to-model training-batch integration check and an input dtype assertion. `export_all_models.py:119` already casts features to float32, which explains why the export/evaluation convenience path can run while the dataset-based training path fails.

The local environment used for this check was Python 3.11, torch `2.14.1+cpu`, torchaudio `2.11.0+cpu`; torchvision is absent. This is a reproduction of the dtype contract, not proof of trained accuracy or a fully working environment.

### P1 — Proven: evaluation is used for model selection and threshold tuning

- `train_srm_cnn.py:84–94` builds a subset of the validation data, passes it as the trainer validation loader at `:105–106`, and reports that same loader as a final test at `:122–140`. `retrain_srm_native.py:53–73,83–101` does the same. `reeval_srm_cnn.py:37–51` uses that same validation directory.
- `train_xgboost_meta.py:262–280` trains fusion features from `genimage/val`, which also selects the visual checkpoint. `:396–410` uses its held-out feature set for XGBoost early stopping and then reports final metrics on that same set. This is a validation set, not an untouched final test set.
- `generate_android_constants.py:85–112` chooses the audio operating threshold from the test set; `:145–165` chooses the meta threshold from the same fusion evaluation set. Threshold tuning must be on a calibration/development set, followed by a sealed test evaluation.
- `export_all_models.py:132–133` uses `genimage/val` and `asvspoof2019/test` for quantization calibration, another use of evaluation data during model preparation.
- Create distinct training, model-selection validation, calibration, and sealed test manifests. Obtain fusion training features from out-of-fold base-model predictions or a separate stacking split. Group originals/variants by source photo, prompt, generator version, person/speaker, recording/session, and transcript before splitting. Report cross-generator, cross-dataset, and future-generator results separately from within-dataset results.

### P1 — Proven: export validation samples only one class and ignores the operational threshold

- `export_all_models.py:list_files` returns real files first (`:64–74`). Image pool limit 400 means up to 200 real followed by 200 fake. `visual_calibration_dataset(...,200)` consumes only those first 200 real items. `:159–160` passes the first 100 pool entries, all real, and `validate_models_real` uses only the first 50 by default.
- Audio pool limit 200 means 100 real followed by 100 fake. `specs` consumes first 120; calibration limit 80 and validation limit 60 consume only real samples (`export_all_models.py:178–189`). Both data classes are needed to preserve fake-side activation ranges and catch lost sensitivity.
- `validate_export.py:92–108` refuses export only on classification agreement at 0.5. It prints mean/max score error but imposes no error or AUC/TPR limit. Large confidence damage can still pass when both scores remain on the same side of 0.5. The app audio/meta operating thresholds differ from 0.5.
- `keras_parity_check` prints a max error and returns it (`torch_to_tflite_keras.py:196–210`), but its result is ignored (`export_all_models.py:154–157`). The audio Keras builder has no corresponding independent FP32 parity gate in the main export path.
- Use a randomized, stratified calibration subset from training, including codecs and difficult examples. Gate FP32 reconstruction parity, FP32-to-INT8 AUC change, TPR at selected FPR, calibrated threshold agreement, per-generator sensitivity, max/mean score deviation, and latency. Save labels, file IDs and model hashes with the results. Assess both CPU and actual Android delegate outputs.

### P1 — Proven: higher-resolution training is disconnected from mobile export and fusion

- `train_srm_cnn.py:47–77` allows `DATASET_DIR`/`IMG_SIZE` to select high-resolution data. The YAML high-resolution config is **never loaded** by this script. The result metadata still records 32-pixel input and a native-32 validation name (`:140–144`) even when another image size is selected.
- `build_keras_srm` hardcodes a `(32,32,3)` input (`torch_to_tflite_keras.py:82`); quantization drops every non-32 image (`quantize_int8.py:88–90`), and export chooses only `datasets/genimage` (`export_all_models.py:48,132`). Android likewise hardcodes 32-pixel scaling (`SRMForensicAnalyzer.kt:23,43`). Merely downloading 512-pixel data or setting `IMG_SIZE=256` does not create a 256-pixel deployable model.
- Fusion training computes the SRM score at original native size (`feature_extractor.py:222–225`), while Android always resizes to 32. For high-resolution photos these are different inputs, even when the network is fully convolutional. Native dimension changes also alter feature-map and global-average statistics.
- Make image input size, resize/crop/patch policy, RGB handling, interpolation, model version, checkpoint and representative dataset explicit shared configuration. Retrain and export together. Favor native-resolution patches plus a whole-image semantic view, with matched training/inference pooling, rather than globally shrinking every detailed photo to 32 pixels.

### P1 — Proven stale-contract risk: current artifacts cannot be explained by current training code

- `lfcc_frontend.py:38–39` says every checkpoint records `FRONTEND_ID`, but `ModelCheckpoint` stores only epoch, state_dict, optimizer and best_metric (`callbacks.py:53–58`). Neither loader checks the front-end contract. A recent frontend/architecture change can silently reuse incompatible checkpoints.
- The checked-in `ml/evaluation_results.json` has no dataset fingerprint, actual file list, checkpoint/model hash, frontend ID, class mapping, source revision, confidence interval, or export version. It predates the output schema currently written by `run_full_pipeline.py:156–160`.
- Android's shipped audio threshold JSON reports AUC 0.0151/EER 0.9607, versus this ML results JSON's 0.9760/0.0500. The current generator has polarity-aware code, but the checked-in constant remains old. Regeneration after fixing training and mapping is necessary; the threshold direction cannot be inferred solely from the stale JSON.
- Android's shipped XGBoost code branches on EXIF feature 6 near 0.8 and C2PA feature 7 near 0.9. Current ML extraction defaults these to 0.1 and 0.05 (`feature_extractor.py:48–49,232–233`), and every current fusion training extraction omits provenance (`train_xgboost_meta.py:290,298`). A tree trained exclusively on constant feature columns cannot learn those splits. This is strong evidence of a different/stale training artifact, not proof of which historical run produced it.
- Save a single release manifest linking source commit, feature schema/front-end versions, data manifest and revisions, label maps, checkpoint SHA-256, TFLite SHA-256, generated Kotlin SHA-256, calibration constants, and evaluation report. Reject mismatches in tooling and app startup. Regenerate all derived assets as one release transaction.

### P1/P2 — Proven loader behavior can produce leakage and mislabeled evaluation

- `OpenFakeDataset._scan_dataset` falls back to the entire root whenever a requested split directory is missing (`openfake_dataset.py:72–73`). Missing val/test can therefore become the same files as training. Require explicit split manifests; fail if a requested split is absent/empty.
- `InTheWildAudioDataset` fallback scans the whole root when one split has no audio (`inthewild_audio.py:71–100`), including other explicit split trees, and repartitions by shuffled file order. Preserve declared splits; only permit manifest-driven initial splitting of an unsplit corpus.
- Its documentation says automatic split hashing (`:16`), but implementation uses `rglob` order + global RNG shuffle (`:77–98`); filesystem enumeration order is not sorted or hashed, so membership can differ across systems. For tiny class counts, formulas can even overlap train/val/test.
- `run_full_pipeline.py:97` and `generate_android_constants.py:98` infer class only from the immediate parent folder. A recursive real layout `real/speaker/sample.wav` is labeled fake. Use the discovered class label/file manifest, not a basename guess.
- Image and audio loaders silently turn corrupt or undecodable examples into black tensors or silence with the original class label (`cifake_dataset.py:91–95`, `genimage_dataset.py:96–98`, `openfake_dataset.py:65–66,111–112`, `asvspoof_dataset.py:106–108`, `inthewild_audio.py:138–139`). This introduces synthetic shortcuts and can inflate or poison metrics. Preflight decoding, quarantine bad samples, record all failure counts, and refuse evaluation above a small explicit failure budget.

### P2 — Measured: claimed Python–Android preprocessing equivalence is incomplete

- Audio training uses `torchaudio.transforms.Resample` defaults (`asvspoof_dataset.py:101`, `inthewild_audio.py:134`). Python reference and Android use a custom sinc kernel window `1 - hk²` (`lfcc_reference.py:222–229`, `AudioDecoder.kt:265–271`). That quadratic window is not torchaudio's `sinc_interp_hann`, despite the comments claiming a mirror of the defaults.
- A read-only numerical probe compared both resamplers on a 0.1-second two-tone waveform: maximum PCM error was 0.07150 at 48k→16k, 0.06921 at 44.1k→16k, 0.04294 at 22.05k→16k, and 0.28537 at 8k→16k. RMS differences were 0.00465, 0.00473, 0.00257 and 0.02454 respectively. This proves different waveforms, **not a measured percentage-point accuracy loss**. Both are anti-aliased; rejecting aliases alone does not establish exact parity.
- FFT training calls `to_gray_u8` before FFT (`feature_extractor.py:185`), truncating luma to integer values. Android FFT uses double-precision unrounded luma (`FFTSpectralAnalyzer.kt:38`). The KL analyzer does truncate luma on both sides, so it needs its own separate gray convention.
- PIL bilinear resizing and Android bitmap resizing should not be asserted bit-exact without end-to-end golden inputs. Decoding colors, EXIF orientation and decode sampling also require actual image fixtures across platforms.
- Pin one mathematically specified resampler/window and use it for training and mobile. Test raw decoded media → PCM/RGB → features → model output on shared fixtures, including common sample rates, source formats, silence, short/long clips, portrait/wide images and image transformations. Add real speech/images to golden tests alongside tones.
- Frontend comments also claim torch STFT is float32-only (`lfcc_frontend.py:128,153`); a cheap execution of float64 input+window returned complex128. The current code explicitly casts to float32 at `:159`, rather than being forced to. Fix the inaccurate explanation and choose precision on measured parity/performance grounds.

### P2 — Dataset tools do not download the datasets their names advertise

- `download_all_datasets.py` stores CIFAKE into `genimage` (`:58–64`) and Gary Stafford speech into `asvspoof2019` (`:130–137`). Its audio source currently has only `train`; val/test expected at `:144–153` will be skipped. The script deletes the old audio dataset before confirming replacement (`:21–26`); its `main` bypasses visual download and hardcodes success (`:276–277`). Audio verification counts `.wav` while it writes `.flac` (`:176,196–197,244–245`).
- `download_highres_audio.py` targets 25,000 per class from a source currently containing only 933 per class. Because val begins after 20,000 per class (`:35,47–52`), a clean current run can put all files in training and leave evaluation splits empty. It names raw FLAC bytes `.wav` (`:55–60`) without transcoding.
- `download_advanced_datasets.py` advertises WaveFake/In-The-Wild and GenImage/artifacts but actually downloads Gary Stafford speech and `ngscamdev/deepfake-and-real-images` (`:26,33,83,89`). Default audio request 10,000 makes the val boundary 4,000 per class, also unattainable on the current source. It removes source recording/generator IDs and uses counter-based splitting, defeating grouped evaluation.
- `download_highres_datasets.py` prints `bitmind/diffusion-artifacts` (`:21`) but loads a different source (`:31`). It filters for resolution but preserves no generator metadata and re-encodes JPEG at quality 95. Its source/class mapping requires explicit metadata verification before use.
- `download_hf_quickstart.py` deletes both datasets (`:6–10`), then combines 64-pixel Tiny ImageNet real pictures with large DiffusionDB generated art (`:22,32`). The enormous resolution/source/content mismatch creates an easy dataset classifier, not a defensible general AI detector. Its success message incorrectly reports 1,000 per class per split (`:40`); val/test each request 200.
- Make tools non-destructive, resumable, revision-pinned and idempotent. Preserve original bytes and metadata; use fresh named dataset versions. Validate class counts, source signatures, actual resolutions, split completeness and decode status. Fail with non-zero exit code on partial/failed downloads. Use canonical dataset names honestly.

### P2 — Reproducibility and scaling need engineering before million-image training

- All high-resolution image training is cached as full RGB PIL images (`train_srm_cnn.py:79–80`, `openfake_dataset.py:57–66`). One million 512×512 RGB images need approximately **786 GB of pixel storage**, before Python/process overhead; 1,024×1,024 needs approximately 3.15 TB. This cannot fit 128 GB RAM. Windows worker spawning can worsen copy cost.
- Use indexed shards/WebDataset-style streaming, local NVMe cache, lazy native patch decoding, limited prefetch, and bounded per-worker memory. Maintain dataset IDs and grouping in sidecar manifests. Benchmark I/O, decode CPU, accelerator utilization and checkpoint cadence on a 1% sample before full training.
- `train_xgboost_meta.py:253–260` trusts an old `meta_features_cache.npz` without model, dataset, feature or baseline hashes; baseline JSON is also reused blindly (`:338–340`). Retraining the base detector can leave fusion training on stale predictions. Cache identity must include all upstream inputs; force invalidation on changes.
- `dataset_splits.fingerprint_dir` hashes only paths and sizes (`:39–57`); same-sized modified files pass unchanged. It also uses OS-specific path separators. It is a useful cheap inventory hash, not an exact content fingerprint. Store per-item source IDs/content hashes during download, with normalized relative paths and the actual evaluation manifest.
- Generator grouping/LOGO helpers exist (`dataset_splits.py:66–168`) but no training/evaluation code invokes them. `logo_splits` puts all real photos on train (`:104–105,121–122`), so held groups alone cannot produce binary AUC; explicitly partition source-disjoint real controls for held-out evaluation.

### P2/P3 — Training/export maintenance defects and scientific limitations

- `Trainer` ignores top-level YAML early stopping metric/patience/mode and always tracks AUC max (`trainer.py:51–55,80–94`); audio patches the loop with a closure instead (`train_lcnn_audio.py:102–130`). Refactor monitored metric into one implementation. `gradient_clip` in YAML is ignored because Trainer reads `max_grad_norm` (`:34`); configured `eta_min`, `precision`, `prefetch_factor`, `logging.save_interval` and several model/data fields are not consistently consumed.
- Visual `--device` is printed but not passed into Trainer (`train_srm_cnn.py:43,105–106`), so choosing CPU on a CUDA host still trains on the autodetected GPU. `--amp` defaults true with no disable option (`:37`), and `persistent_workers=True` fails with num_workers=0 (`:90–92`). Audio argument overrides use truthiness and cannot set zero workers (`train_lcnn_audio.py:43`). Gate AMP by actual device type; use a real optional boolean.
- Trainer advertises EMA but implements none (`trainer.py:17`). Checkpoints are only best checkpoints, lack RNG/scaler/callback state and contract metadata, and cannot reproduce a faithful resume. Gradient accumulation always divides by the full configured step count, even for a shorter final accumulation group (`:118,124`); losses average batches instead of weighting samples. Use stable logits + BCEWithLogitsLoss to avoid sigmoid saturation/AMP issues.
- `assert_scores_sane` checks non-finite, constant scores and class presence (`metrics.py:42–63`), but **does not check AUC inversion**, contrary to multiple comments. AUC below 0.5 can also be genuine distribution shift; it should prompt diagnosis, not automatic polarity reversal or refusal to report bad OOD results. One-class `compute_auc` returns 0.5, masking an invalid evaluation instead of failing (`:70–71`). EER is a nearest ROC crossing estimate, not a precision guarantee; report confidence intervals and low-FPR metrics.
- `quantize_tflite_model` is documented as taking a TFLite flatbuffer but calls `from_saved_model` (`quantize_int8.py:37–44`), so flatbuffer input is unsupported. Its size calculation also assumes a file path. Rename to a SavedModel converter or remove the unused interface. Dynamic-range fallback is at least disclosed by the report, but asset filenames still say int8; release metadata should specify the actual quantization/delegate contract.
- XGBoost export drops the missing-value default branch (`train_xgboost_meta.py:81–86,105,203`), so NaN always follows the emitted else branch instead of the learned missing branch. Current training drops NaNs; current finite inputs mitigate this, but future missing features require explicit schema handling and emitted missing-branch parity. Its parity is a NumPy re-evaluation of the same AST, not executed Kotlin float arithmetic. Generated Android files are written before parity passes (`:449–457`); stage outputs and only install validated artifacts.
- `setup.py` pins torch 2.4.0 but leaves torchvision/torchaudio/TensorFlow/XGBoost/datasets unpinned (`:9–28`), and `requirements.txt` omits the torch trio entirely. Package `ai-edge-torch` is always installed even though the active Windows path exists specifically because that export stack lacks Windows support. Split train/export/dev extras, use a tested lockfile and supported platform constraints. Namespace generic packages `data/models/utils` under `onndetect` to prevent collisions. The generated egg-info SOURCES lists many absent files and lacks new ones; regenerate rather than use it as inventory.
- Dockerfile is only a base image + comments: no copied code, dependency install, workdir or execution entrypoint. Makefile `eval` evaluates Python submodels, not the Android end-to-end pipeline; `package` is POSIX-only and `clean` is destructive. Document a working reproducible environment and use portable controlled scripts.
- `baseline_aeroblade.py` uses a single SD VAE and plain pixel MSE (`:60–77`), despite a docstring promising LPIPS fallback. It is an unexecuted reconstruction baseline, not a replicated official AEROBLADE result or a universal detector. Retain it as a diagnostic experiment, and use the authors' actual benchmark implementation for a paper comparison.

## Improvement program suitable for offline deployment

1. **Repair validity first:** correct source mappings; add dtype conversions; forbid split fallbacks; lock the current environment; regenerate frontend/model/fusion assets together; establish real sealed tests. Repeat metrics using the actual exported Android path. A larger dataset cannot compensate for wrong labels or inconsistent preprocessing.
2. **Build a source-balanced data mixture:** include multiple diffusion, autoregressive and GAN generations, image editing/inpainting, commercial platform exports, photorealistic and stylized content, and genuine real photographs from many cameras. Include difficult real negatives such as denoised/HDR/night-mode smartphone images, CGI, illustrations, scans, screenshots, cartoons and edited photos as separately labeled categories. Avoid treating all non-camera imagery as generated by AI.
3. **Benchmark image branches:** maintain a matched native-resolution residual/patch branch; benchmark frozen large representation teachers (e.g. CLIP/DINO-family) for cross-generator signal, then distill into a measured mobile student. Compare compact pretrained backbones and MobileCLIP-family alternatives under an explicit latency/RAM/model-size budget. Larger models may serve training/benchmarking without running on the phone. Select on sealed cross-generator results and device measurements, not published within-dataset accuracy alone.
4. **Strengthen audio diversity:** use official spoofing train protocols plus genuinely independent out-of-domain speech, synthesis methods, speakers, languages (including Indian languages), codecs, background noise and voice conversion; group by original recording/speaker/transcript. Compare current LCNN with compact raw-waveform or time-frequency detectors and distillation from SSL audio teachers. Do not assume speech spoofing detectors detect AI music or sound effects; those need separate data, labels and evaluations.
5. **Match real transport paths:** image crop/recompression/downscale/blur/screenshots and audio MP3/AAC/Opus, resampling, telephony bandwidth, playback/re-recording, clipping, silence and partial manipulation. Augment both real and synthetic classes with the same nuisance distributions. Train and validate multiple aligned windows/patches; aggregate with calibrated uncertainty so localized edits are not hidden by a single global 32-pixel or 4-second sample.
6. **Calibration and honest UI:** report AUC, balanced accuracy, EER, TPR at FPR 1% and 0.1%, per-generator/source/codec/language results, bootstrap confidence intervals, reliability/Brier/ECE, and selective performance when the detector abstains. Fit calibration on held-out data for the final INT8/mobile score. Detect low quality, out-of-domain inputs and model/runtime failures; output an inconclusive status instead of a misleading probability. No score can guarantee detection of every future platform generator.
7. **Release discipline:** one manifest and golden media suite tie code, model, features, constants, class semantics, data and metrics together. Acceptance includes actual mid-range/low-end devices, offline behavior, RAM/energy/latency, delegate coverage and repeatability. Use reproducible ablations so each additional dataset or branch must improve generalization, not just bulk count.
