**Date:** 2026-10-21
**Release measured:** `onn-20261020-v6` (shipped)
**Corpora:** `D:\onn_data\openfake_visual` (3,600 records, 6 splits), `D:\onn_data\asvspoof_inthewild_audio` (2,400 records, 4 splits)
**Companion document:** `docs/STATE_OF_THE_ART_REVIEW_2026-10-20.md`

## 1. The headline: a frozen VFM probe is worth +0.205 AUC

The shipped Engine C is a distilled CNN student. A frozen vision tower with a
769-parameter linear probe head — no fine-tuning of the backbone — was fitted
on the `stacking` split, the regularisation selected on `fusion_val`, and
`calibration`/`test` read once.

| Detector | dim | stacking (fit) | fusion_val | calibration | **sealed test** |
|---|---|---|---|---|---|
| MobileCLIP2-S0 *(documented, not shipped)* | 512 | 0.9688 | — | — | **0.5145** (chance) |
| **DINOv2-S/14 + registers** | 768 | 0.9780 | 0.8273 | 0.8053 | **0.8358** |
| **DINOv2-B/14** | 1536 | 1.0000 | 0.8486 | 0.8341 | **0.8541** |
| **SigLIP-B/16 (224 px)** | 768 | 1.0000 | 0.8569 | 0.9008 | **0.8919** |
| **Shipped Engine C (distilled CNN student)** | — | — | — | — | **0.6871** |
| Shipped fusion (Engine A + Engine C) | — | — | — | — | 0.7152 |

**SigLIP-B/16 gains +0.205 test AUC over the shipped Engine C**, and +0.177
over the whole shipped fusion, with a 769-number head.

The fit-split AUCs of 1.0000 are exactly the memorisation the repo's own
`docs/DUAL_ENGINE_CASCADE.md` warns about — and they are why the selection
is done on `fusion_val`, never on the fit split. MobileCLIP2-S0's 0.9688 fit
score became a 0.5145 held-out score; the same failure mode is visible here
and is contained by the protocol.

## 2. The source shortcut survives every backbone

Per-source false-positive rate on the sealed test split (400 images):

| Detector | laion | pexels | docci | imagenet |
|---|---|---|---|---|
| Shipped Engine C (student) | **0.5185** | 0.3333 | 0.1765 | 0.0606 |
| Shipped fusion | 0.4444 | 0.3478 | 0.2941 | 0.1515 |
| DINOv2-S/14 probe | 0.3622 | 0.2926 | 0.3075 | 0.1265 |
| DINOv2-B/14 probe | 0.3093 | 0.3007 | 0.2921 | 0.0154 |
| **SigLIP-B/16 probe** | **0.2897** | 0.2516 | 0.2787 | 0.0199 |
| **Required bound** | **≤ 0.05** | ≤ 0.05 | ≤ 0.05 | ≤ 0.05 |

A better backbone **reduces** the shortcut (LAION 0.5185 → 0.2897) but does
not remove it. See §3 for why.

## 3. The root cause, measured: the corpus leaks the label through `source`

`ml/scripts/audit_source_bias.py` on the real manifests:

```
split         source              real    fake   status
test          docci                 17       0   REAL ONLY - shortcut
test          imagenet              33       0   REAL ONLY - shortcut
test          laion                 81       0   REAL ONLY - shortcut
test          openfake               0     200   FAKE ONLY - shortcut
test          pexels                69       0   REAL ONLY - shortcut

source-only classifier accuracy: 1.0000
```

**A trivial "which source is this?" classifier scores 100%.** Every fake
image comes from `openfake`; every real image comes from `laion`/`pexels`/
`docci`/`imagenet`. The label is a deterministic function of the source, so
*no* model can learn synthesis from this corpus without also learning the
source — and the per-source FPR breakdown is structurally incapable of
separating "the detector is biased" from "the source IS the label".

The **audio** corpus does not have this defect:

```
calibration   asvspoof2019         130     130   both classes
calibration   inthewild             70      70   both classes
source-only classifier accuracy: 0.5000
```

So the two shortcuts have **different causes and different fixes**:

| Corpus | Shortcut | Cause | Fix |
|---|---|---|---|
| image | `source` perfectly predicts the label | corpus construction | B-Free protocol: generate synthetic twins *from* the real images (SDEdit / autoencoder reconstruction / inpainting) so each real image and its fake share source, semantics and aspect ratio |
| audio | `inthewild` real speech 24.3% FPR, `asvspoof2019` 4.6% | **channel/noise**, not source: ASVspoof bona-fide is clean studio audio, in-the-wild is noisy and compressed | apply the *same* codec/channel chain to both classes |

## 5. The phase-spectrum route does not work as a scalar feature

CVPR 2026 feeds the phase into a cross-modal transformer. The hypothesis was
that a scalar phase summary could slot into the existing fusion.

**It cannot.** Every scalar summary of the phase-only reconstruction is
either numerically constant or below chance (§4). The reason is structural:
the phase of a natural image is nearly uniform, so the phase-only
reconstruction is nearly the same image for every input.

Feeding the phase reconstruction through the *existing* residual detector
confirms it (`ml/scripts/evaluate_phase_route.py`):

| Input to Engine A | AUC | EER | std |
|---|---|---|---|
| the original image | **0.6584** | 0.3950 | 2.1e-01 |
| the phase-only reconstruction | **0.4969** | 0.4975 | 4.7e-02 |
| the laundered phase reconstruction | 0.4981 | 0.4950 | 4.7e-02 |

The 0.6584 for the original reproduces the shipped Engine A test AUC
exactly, which is a **verification of the measurement harness itself**.

**Conclusion:** the phase spectrum needs a *learned* consumer — a new model
and a new release. It cannot be a slot in the existing fusion. The plan's
P1.3 is therefore downgraded from "add a feature" to "replace `fft_score`
and `kl_score` with a phase-conditioned model in the next release".

## 6. Toolchain: the frozen tower exports to ONNX, but not yet to TFLite

`ml/scripts/export_vfm_probe.py`, SigLIP-B/16:

| Stage | Result |
|---|---|
| PyTorch → ONNX (opset 17) | **343.4 MB** (86 M params, fp32) |
| ONNX ↔ PyTorch parity | **max abs error 5.54e-06** |
| ONNX → TFLite (onnx2tf) | **fails** |

The TFLite failure is specific and fixable, not fundamental: onnx2tf cannot
handle SigLIP's *interpolated* position embedding and mis-orders the
hidden axis (`LayerNormalization` sees 196 where it expects 768). The
standard fixes are a ViT-aware converter (Google's `ai-edge-vit` / LiteRT
ViT ops) or a parameter-replacement file for the LayerNorm.

The APK-size consequence is real and must be decided explicitly: SigLIP-B/16
is 86 M parameters ≈ **86 MB INT8**, against a 21 MB APK today and a
153 KiB Engine C. DINOv2-S/14 is 21 M ≈ 21 MB INT8 and reaches 0.8358.

**Intermediate option, not yet measured:** ship the tower in ONNX-format
LiteRT and run the probe head on the host. The repo's `LiteRTInferenceEngine`
already binds a `.tflite` file, so this needs an engine change.

## 7. How to reproduce

```powershell
# 1. the source-shortcut audit (both corpora)
python -m ml.scripts.audit_source_bias --data-root D:\onn_data\openfake_visual
python -m ml.scripts.audit_source_bias --data-root D:\onn_data\asvspoof_inthewild_audio

# 2. the frozen-tower probe measurement
python -m ml.scripts.evaluate_vfm_probes `
    --data-root D:\onn_data\openfake_visual `
    --output-dir D:\onn_data\runs\vfm_probe_eval `
    --towers facebook/dinov2-with-registers-small google/siglip-base-patch16-224 facebook/dinov2-base

# 3. the analytic-feature table (clean vs laundered)
python -m ml.scripts.evaluate_analytic_features `
    --data-root D:\onn_data\openfake_visual `
    --output D:\onn_data\runs\vfm_probe_eval\analytic_features.json

# 4. the phase route
python -m ml.scripts.evaluate_phase_route --data-root D:\onn_data\openfake_visual

# 5. the export
python -m ml.scripts.export_vfm_probe `
    --data-root D:\onn_data\openfake_visual `
    --output-dir D:\onn_data\runs\vfm_probe_export `
    --tower google/siglip-base-patch16-224
```

Outputs land in `D:\onn_data\runs\vfm_probe_eval\`:
`vfm_probe_report.json`, `analytic_features.json`, `phase_route.json`, and
the per-tower embedding caches.

## 8. What this changes in the plan

| Plan item | Before | After the measurement |
|---|---|---|
| P0.2 (fix the corpus) | "rebuild the real class to match aesthetic statistics" | **the `source` field must stop predicting the label** — a source-only classifier currently scores 100% |
| P1.1 (ship a frozen VFM) | "SigLIP-B/16 or DINOv2-S/14, orthogonal subspace" | **SigLIP-B/16, l2=30, 769 params, 0.8919 test AUC** — the tower choice is settled by measurement |
| P1.1 (ship the tower) | "22 MB INT8 is acceptable" | **86 MB INT8 for SigLIP / 21 MB for DINOv2-S** — an explicit APK-size decision, and the TFLite converter needs a ViT-aware path |
| P1.3 (phase spectrum) | "add a phase slot to the fusion" | **not viable as a scalar** — needs a phase-conditioned model, or the slots are replaced |
| P0.2 (audio) | "match the channel distribution" | confirmed: the audio `source` is clean, the shortcut is the **channel**, so the codec-matched corpus is the fix |
